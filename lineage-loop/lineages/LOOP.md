# 무한 개선 루프 (모든 계통 공통)

목표는 게임 규칙 전반에서 더 강한 로직을 찾는 것이다. 규칙·환경은 `BRIEF.md`, 판단 원칙은 `GROWTH.md`를 따른다. 공통 문서에 실험별 요령을 계속 추가하지 않는다.

## 한 사이클
1. **관찰·가설:** 현재 근거에서 부족한 점과 변경 가설을 고른다. 작은 수정·삭제·처음부터 만든 단순 설계 모두 후보가 될 수 있다. 진행 중인 실험이 있으면 먼저 마무리한다.
2. **탐색:** 후보는 자기 계통의 별도 디렉터리에 구현한다. `bot/`은 유지한다. 로컬 평가는 `run-job.js`를 통하고, 실행 오류·누락은 무승부나 정상 결과로 세지 않는다.
3. **확인:** 채택할 후보 하나를 정한 뒤 `node loop/check.js <계통> <후보 디렉터리>`를 실행한다. 도구가 웨이브 시작의 최선과 후보·지도·상대를 고정한 다음 새 시드 2개를 뽑아 같은 조건·양 진영으로 평가한다. 현재 기본 풀은 버전당 160판이다. 보고서는 판단 근거이지 자동 승격 점수가 아니다. 동일 후보·기준의 시드를 다시 뽑지 않는다.
4. **판단·기록:** 원자료와 상충하는 결과를 보고 채택 또는 기각한다. `NOTES.md`에 이유와 근거 경로, `CURRENT.md`에 현재 상태를 남긴다. 확인 결과를 보고 후보를 수정했다면 새 후보의 확인은 별개이며 이전 실패도 이력에 남긴다.

## 웨이브 종료
웨이브는 문맥의 경계이지 성능 향상의 단위가 아니다. 실험은 여러 웨이브에 걸쳐 이어갈 수 있으나 등록된 평가가 끝나기 전에 다음 웨이브는 시작하지 않는다. 한 웨이브에서 채택은 한 번이다.

- 채택: 확인된 후보를 그대로 `bot/`에 반영하고 `NOTES.md`에 `ready: r<번호> — 변경·근거`를 추가한다. `node loop/runner.js finish <계통> adopt "판단 이유" <report.json>`가 코드 일치·근거를 검사하고 `bot/`, `NOTES.md`, `CURRENT.md`를 버전 커밋한다.
- 기각: `bot/`을 유지하고 `node loop/runner.js finish <계통> reject "판단 이유"`.
- 미완료: `bot/`을 유지하고 현재 상태를 기록한 뒤 `node loop/runner.js finish <계통> incomplete "남은 일"`. 미완료는 채택·성장으로 세지 않는다.

등록된 작업을 기다린 뒤 종료한다. 실행기가 정상 종료와 명시적 채택을 확인해야 export하며, 남은 실험 이력은 웨이브 커밋으로 남긴다. 확인되지 않은 `bot/` 변경은 자동 되돌림 없이 보존하고 루프를 중단한다. 확인 평가가 실패하면 원인을 조사하며 유리한 시드로 재추첨하지 않는다.

새 계통에 기존 봇이 없다면 규칙서에서 출발해 후보를 만든다. 첫 확인에는 이전 최선 비교가 없으므로 성능 향상이 아닌 초기 기준선으로 기록한다.

## 다중 에이전트 지점
사고가 무거운 세 지점에서는 Workflow 도구로 독립 에이전트를 병렬로 쓴다(틀·규칙·판단 기준은 `loop/WORKFLOW.md`). 1의 가설을 구현하기 전 관점별 가설 패널과 반박 심사, 2의 첫 평가 전 구현 검토, 3의 보고서 뒤 채택 전 독립 반박. 에이전트는 읽기·분석·반박만 하며 경기 실행과 기록·finish는 계통 담당이 직접 한다. 평가 배치 수를 늘리는 용도로 쓰지 않는다. 결과는 판단 재료이며 요지를 `NOTES.md`에 남긴다.
