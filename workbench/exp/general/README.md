# Unknown-map generalisation study

All input is local and read-only. Every new write is inside `exp/general/` except the requested Korean report. No games, network requests, opponent-source reads, uploads or commits.

`tables.json` was created first as an explicit incomplete checkpoint, and is the authoritative deliverable. Final raw caches are gzip. The frozen top population is fixed at the first inventory; elite membership has its own refresh timestamp and can alias a top game without duplicating the physical replay.

Run sequentially from the repository root:

```sh
python3 exp/general/setup.py
node exp/general/verify_geometry.js
node exp/general/scout.js
node exp/general/extract.js
python3 exp/general/refresh_elite.py
node exp/general/extract.js
node exp/general/enrich.js
python3 exp/general/repair_metadata.py
python3 exp/general/aggregate.py
python3 exp/general/join_conversion.py
python3 exp/general/fit.py
python3 exp/general/cap_validation.py
python3 exp/general/annotate_models.py
python3 exp/general/verify_fits.py
node exp/general/deep.js
python3 exp/general/elite_inventory.py
python3 exp/general/finalize.py
python3 exp/general/make_report.py
python3 exp/general/qa.py
python3 exp/general/summary.py
```

Do not run extraction and enrichment together: each owns at most two workers. Resource gates are memory-pressure availability <10% or disk free <21 GiB. A `nice` attempt was rejected by the sandbox; no reduced-priority claim is made. Independent graph verification and static survey are short, serial computations. Resume gzip extraction by unique replay key. Each active worker run uses its fixed in-memory task list; the provided refresh step is sequential.

The reused atlas reconstruction writes only `exp/general/geometry/`; the original atlas/spatial/opening/pocket/conversion files are never mutated. `setup.py` generates the basic adapted recount. `atlas_extended.js` adds independently counted pocket intake and path-distance safety, and is maintained as a separate file. It is not regenerated by `setup.py`.

The fast decoder omits sonar events but exposes `sonarBySender`. `lib.js` now assigns sender teams from initial/split IDs directly. `repair_metadata.py` corrects the original batch's ping fields and stalled-game eligibility, checking the independently reconstructed filter. Behavioral counts are preserved. The first smoke-test error remains in `errors.jsonl`; resolved keys and unresolved errors are listed in final QA.

Checkpoint numbers condition on game survival, never carry an ended game to r250. Conversion fitting conditions on 500-round games. Safety counts sample every five rounds in r300–499, using static legal paths including portals and wrap, with unreachable distances represented separately. Classes are descriptive: r100 absent; otherwise pocket-natural share >=20%; otherwise r100 middle share >=40%; otherwise distributed.

Generalisation uses 15 known layouts and 10 map-name families. Nested model selection always leaves out an entire family internally; outer tests remove one layout, every layout of one map name, or one of five fixed geometry groups. The geometry grouping is fixed before fitting: isolation, approach >=40, area >=1500, seed king >=8 on area <=1100, otherwise compact contact, in that order. Median leaves and monotone fits use equal total family weight. The independent validation script refits the selected outer-fold model with a separate Fraction-weight implementation and recounts MAE/RMSE/baseline; it does not independently reselect the inner winning model. Map-family bootstrap intervals are descriptive sensitivity checks, not guaranteed unseen-map coverage.

Spawn support in a viewed tile is runtime-observable through countdown>=0, but the replay does not retain countdown values. Full-map gap means are oracle references only. Successful natural appearance is a lower service-rate proxy, not a respawn-attempt rate. Allied vision union is a communication upper bound, not guaranteed sonar sharing. Full-map frontier, pocket fraction, isolation and potential supply are not presumed known at r30.

`elite-inventory.json` records the final local unseen-map check and a concrete appendix plan. If sprint maps have appeared, freeze and evaluate them before refitting any rules; do not silently fold them into the 15-layout training corpus. The inventory script itself only identifies them; it does not pretend to reconstruct an unseen map with missing hidden spawn ranges.
