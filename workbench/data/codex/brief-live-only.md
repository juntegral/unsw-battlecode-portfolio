## Background
- `data/online/smoke/run-pair.sh <label> <botdir> "<card ref>" [opponent ids]` wraps `python3 tools/smoke.py pair …`: it uploads the bot in `<botdir>` as a temporary submission, plays 15 maps against each opponent, swaps the live bot back, posts notices to Discord through `tools/meowbot.py --announce-file`, and `tools/pair_report.py <label> --post "<ref>"` posts the result. With `BASELINE=1` it first plays the live bot ("old" half), then the new bot.
- Every temporary upload gets the description `paired smoke test` (see `smoke.py`, the `--desc` passed to `submit.js upload`). On the team's submissions page nobody can tell the versions apart. The server does not allow changing a description later (PATCH and PUT return 405), so it has to be right at upload time.
- To get more games of the live bot for the comparison baseline, on 5 Oct the same bot had to be uploaded again as a "new" bot (labels `bl17594b-test`, `bl17594c-test`), which created two more versions of identical code. `pair_report.baseline()` pools every pair state whose `old` half is complete and was played by the live submission id.
- `node tools/subs.js list --json --last 40` prints our submissions as JSON (fields include `id`, `name`, `version`, `status`, `description`); the active one has `status: "active"`.
