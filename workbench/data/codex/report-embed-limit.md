# Embed 길이 제한 수정 보고

`tools/meowbot.py`에 공통 `clamp_embed` 헬퍼를 추가했다. 모든 Discord embed 변환, 출력 미리보기 및 게시판 묶음이 이 헬퍼를 거친다. 필드 값 1024자, 필드 이름·제목 256자, 설명 4096자, 필드 25개, 전체 6000자를 제한한다. 전체 계산에는 footer와 author도 포함하고 각각의 길이도 제한한다. 잘린 문구에는 `…`를 붙이고, 후보 필드에는 사용 가능한 PR 또는 카드 링크를 덧붙인다. 제한 안의 문구와 레이아웃은 유지한다.

`tools/test_meow_embed.py`를 추가했다. PR #35를 가리키는 1500자 기제 설명, 후보의 전체 길이와 카드 링크, 짧은 문구 보존, 개별 한계와 전체 한계, 원본 보존·재적용, 게시판 묶음을 오프라인으로 검증했다.

`tools/`에서 `python3 -m unittest discover -p 'test_*.py'`를 실행한 마지막 5줄:

```text
.........................................................................
----------------------------------------------------------------------

OK
```

검증 제한: `--preview-candidate-pr 35`는 GitHub 조회를 수행하고 열린 PR을 요구한다. 브리프가 네트워크를 금지했고 해당 PR은 수동 병합되었다고 명시했으므로 실행하지 않았다. 실제 PR #35 manifest는 다른 저장소에 있으므로 읽지 않았다. 브리프에 제시된 길이를 재현한 단위 테스트에 의존했다. 실제 Discord 전송은 수행하지 않았다.

커밋과 네트워크 요청은 하지 않았고 비밀 파일은 읽지 않았다. 코드 변경은 지정된 두 파일에 한정했다. 기존 `docs/PROMISES.md` 수정은 건드리지 않았다. 브리프가 별도로 요구한 이 보고서를 마지막으로 작성했다.
