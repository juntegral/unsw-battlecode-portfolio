# 집계 정의 (결과 조회 전 고정)

- 범위: one5–one14 라벨의 unranked `*-old/`에서 완료 JSON과 기보가 모두 있는 우리 팀 경기. 경기 ID 중복 제거; 실제 버전은 기보의 bot id와 versions.tsv로 결정.
- 진주 rT = r0..T-1에 우리 용이 먹은 모든 진주(자연·사체 포함). 길이와 생존 수 rT = roundStart(T)의 상태. 일찍 종료된 경기는 최종 상태를 유지한다. 여왕이 살아 있는 채 종료된 경기를 이후 사망으로 만들지 않는다.
- 여왕 = 시작 시 우리 편 최저 dragon id, 분열 후에도 같은 id. 사망 비율은 관측된 경기 전체가 분모; 사망 라운드 중앙값은 죽은 경기만 사용하며 검열을 보정하지 않는다.
- 포털 = r0..99에서 실제 성공한 이동이 portal edge를 통과한 횟수. 분열 = 같은 구간의 dragonSplit 이벤트 수.
- 사망 = r0..199에서 벽, 자기 몸, 아군 몸, 적 몸, 적이 시작한 머리 충돌 피해자(rammed) 각각을 센다. 우리가 시작한 머리 충돌·아군 머리 충돌·기타도 별도로 보존한다. 머리 충돌에서 우리 쪽이 공격한 사망을 rammed로 합치지 않는다.
- 시작 칸 = 우리 여왕의 최초 head. 거리 = 벽을 통과하지 않고 포털을 반영한 정적 지형의 최단 이동 걸음(토러스). 용 몸은 무시한다. 각 경기의 먼 턴/우리 전체 턴 비율을 구한 후 경기 간 평균; 검산용 토러스 맨해튼 비율도 저장한다.
- 모든 요청 지표의 표는 지도 × 실제 버전이며 평균 [경기 수]. 여왕 사망 중앙값만 정의상 중앙값 [죽은 경기 수/전체 경기 수]. 없는 자료는 — [0].
- 단계 후보: 연속 버전 평균의 변화율이 이전 평균 대비 엄격히 35% 초과. 이전 평균 0에서 양수가 되면 비율이 정의되지 않으므로 `0→양수`로 별도 표시.
- 지속: 다음 버전도 존재하며, 그 이후 자료가 있는 모든 버전의 평균이 최초 경계 이전 평균보다 같은 방향으로 35% 넘게 떨어져 있어야 한다. 마지막 버전의 변화는 후속 확인 불가. 평균이 돌아온 것은 지속 단계가 아니라 되돌아온 변화다.
- 표본 조건: 경계 양편과 후속 버전에 각 지도당 최소 2경기가 있으면 반복 관측 후보, 하나라도 1경기면 얇은 표본 후보로 별도 표에 모두 기록한다. 이는 통계적 유의성·인과 판정이 아니다. 같은 상대끼리 재집계해 상대 구성이 바뀐 영향을 별도로 보여 준다.
- 원자료 games.jsonl; 고정 목록 manifest.json; 단계·평균은 report 생성 스크립트가 재계산한다. 추가 자료는 최종 표 생성 직전에 목록을 다시 고정하고 포함한다.

재현: 저장소 루트에서 아래 명령을 순서대로 실행한다. `count.py`는 목록을 새로 고정하고 캐시에 없는 경기만 읽는다. 기존 고정 자료의 표만 재생성할 때는 첫 명령을 생략한다. 파서/정의를 바꿨다면 games.jsonl을 그대로 재사용하지 않는다.

```sh
nice -n 10 python3 -B data/codex/astra/regress/count.py
nice -n 10 python3 -B data/codex/astra/regress/tables.py
nice -n 10 python3 -B data/codex/astra/regress/validate.py
nice -n 10 python3 -B data/codex/astra/regress/compose.py
```

계측 실행 동안 이 환경은 nice의 setpriority를 거부했다. 모든 Python 작업은 하나씩 직렬 실행했다. 원자료에는 각 기보 SHA-256과 경기·버전·상대·진영·라운드·사건 번호가 있다. 상대 bot id는 빈 문자열이어서 같은 상대 팀이라도 같은 상대 버전인지는 모른다.
