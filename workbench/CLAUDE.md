# unsw-swarm

UNSW Battlecode 2026(심해 드래곤) 봇의 새 계통이다(2026-10-01 시작).

> **2026-10-01 이후 현재 상태와 목표는 `AGENTS.md`가 우선한다.**
> - qualifier는 처음 보는 지도에서 7판 4선승이고, 제출 마감은 10/9 15:00 KST다.
> - 온라인 대전 신청은 중단됐다.
> - 개발은 다이어그램 우선(`docs/arch/`)으로 한다.
> - 작업 대기열은 `docs/WORKQUEUE.md`다.
> - 아래 '대전' 규칙과 웨이브 절차는 당분간 쓰지 않는다.

- **사명:** 상위 7팀(레이팅 1900 이상, 웨이브 상대)을 이기는 봇을 **시스템 단위로** 설계하고, 결과로 판정한다.
- **출발점:** `unsw-heuristic`의 점검(`research/CHECKPOINT-2026-10-01.md`)이다.
  - 기능 하나씩 쌓기(12웨이브)는 상위 6팀 9.0%에서 움직이지 않았다.
  - 우리 봇과 상위권은 경제 엔진이 다르다.
  - 81승 중 75승이 벽으로 갈라진 세 지도(Autarky, Prisoners Dilemma, Portals)에서 나왔고, 다섯 지도는 0/450이다.
- **사용자 결정(2026-10-01):**
  - 새 계통과 판정 재설계로 간다(C+D).
  - 여러 엔진을 지도별로 쓴다. 필요하면 지도마다 따로 쓴다("대찬성").
  - 지금까지의 기보와 가설 검증 자료를 **전부** 활용한다.

## 먼저 읽을 것
1. `ENGINE.md`: 봇 전략의 단일 설계서. 엔진, 지도별 배정, 국면별 역할, 목표 수치, 근거가 있다.
2. `EVAL.md`: 판정 규약. 상위 6팀 합산 웨이브, 검정력, 진단 지표 다섯.
3. `DECISIONS.md`: 사용자 결정과 설계 결정 기록.
4. `research/KNOWLEDGE.md`: 물려받은 모든 자료의 색인. 기보, 캐시, 연구, 판정, 코드가 있다.

## 규칙
- **원격 작업은 허용한다.**
  - API 키(`~/Downloads/api.txt`)로 제출 업로드, 대전 신청, 기록 다운로드를 할 수 있다.
  - 키는 화면, 파일, 커밋, 로그에 남기지 않는다. 자식 프로세스에 환경변수로만 넘긴다.
  - 원격 작업은 `data/online/REMOTE-LOG.md`에 적는다(도구가 자동으로 적는다).
- **대전**
  - 지금은 비랭크 스크림만 한다(사용자 2026-09-30).
  - 상대는 상위 7팀 웨이브다(306, 70, 20, 801, 264, 46, DEV 545).
  - 성적은 상위 7팀 기준으로만 본다. 레이팅, 순위, 낮은 팀 판은 쓰지 않는다(사용자 2026-10-01 00:25).
- **올리기만 한다.** 되돌리기는 사용자 몫이다.
  - 후보가 준비되면, 우리 비랭크 세트가 돌고 있지 않을 때 곧바로 올린다.
  - 웨이브는 `active:<id>`로 신청한다.
- **분석**
  - 누적 전체 모집단을 쓰고, 표본으로 끝내지 않는다.
  - 먼저 분류하고 크기를 적은 뒤, 고른 기보를 정독한다.
  - 앞선 실험체의 판이 1차 표본이다.
  - 핵심 수치는 따로 다시 센다(독립 재계산).
  - 토큰을 아끼지 않는다.
- **역할 분담**
  - Codex(gpt-6.1-sol, 추론 max, `codex exec`): 딥 리서치와 긴 연구
  - Claude: 전략, 설계서, 판정, 조율
  - 구현 에이전트: 버전 구현
  - 사용자가 다른 창(Orca)에서 Codex를 돌릴 수 있으므로, 사용자에게 준 지시문을 다시 띄우기 전에 묻는다.
- **기계 한도**
  - 로컬 판은 동시 6판까지다.
  - 디스크 여유가 20GB 미만이면 새 판을 시작하지 않는다.
  - 무거운 분석은 nice로 돌린다. 부하만으로는 결과가 바뀌지 않는다. 판정은 명령 수로 잰다.

## 일하는 방식
- **버전 하나의 흐름**
  1. `ENGINE.md`에 가설과 목표 수치를 적는다.
  2. `versions/vN/VERSION.md`에 사전 등록한다.
  3. 구현한다.
  4. 로컬에서 점검한다(빌드, CPU, 시간 초과, 진단 지표 방향).
  5. 온라인 3웨이브 합산으로 판정한다.
  6. `DECISIONS.md`와 사용자 점검으로 마무리한다.
- **토글을 쌓지 않는다.** 엔진과 지도별 배정을 버전 단위로 바꾼다.
- **기능 표식은 봇에 남긴다.** 다만 "상황이 오는가"를 보는 진단일 뿐, 채택 기준이 아니다.
- **로컬 흉내 상대 결과로 거르지 않는다.** 2026-09-30에 여러 번 온라인과 어긋났다.

## 명령
- 한 판: `tools/unswbc run maps/online-20260927/<지도>.map bot bots/proxy4_king --sandbox --seed 1 -o game.replay`
- 동작 지문: `node tools/fingerprint.js --same benchmark bot --maps portals,slithery_fight`
- 올리기: `node tools/submit.js upload bot --name <이름> --desc "<설명>" --confirm`
- 웨이브: `node tools/online_wave.js active:<id> <이름> "<설명>" <세트> --vs <지난 세트>`
- 질량 장부 추출: `node tools/mass_ledger.js extract online <세트> --jobs 2`
- 결정 행 추출: `node tools/decisions.js extract online <세트> --jobs 2`
