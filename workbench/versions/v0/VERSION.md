# v0: 엔진 선택 층 (토대, 행동 변화 없음)

- **날짜:** 2026-10-01
- **상태:** 로컬 점검을 통과했다. 올리기와 웨이브는 조정자와 사용자가 정한다(아래 "온라인에 올린다면").
- **기준점:** stack11(제출 13393) = `benchmark/`
- **고정 사본:** `versions/v0/bot/`. 이 버전을 커밋할 때의 `bot/`와 같다.

## 1. 가설 (사전 등록)
- **행동 변화 없음. 이것은 토대다.**
- 전략은 바꾸지 않는다. 대신 둘을 세운다.
  - 지도별 엔진 선택 층
  - 새 판정 도구 `eval/system_report.js`
- **성공 기준:** 확인한 모든 판에서 동작 지문이 stack11과 같다. 하나라도 다르면 v0는 실패다.
- 진단 지표 목표는 없다(행동이 같으므로).

## 2. 바꾼 것

| 파일 | 내용 |
|---|---|
| `bot/policy.hpp`(새) | 배정표와 인자 구조. 아래 "구성"을 본다 |
| `bot/engine.hpp`(새) | 떼 엔진 `EngineSwarm`. v0에서는 같은 `Planner` 객체의 `decide()`로 넘기기만 하는 빈 엔진이다 |
| `bot/main.cpp` | 차례마다 두 가지를 한다(9줄). 아래 "차례마다"를 본다 |
| `bot/params.hpp` | `ENGINE_TAG = true`(표식 스위치) |

**`policy.hpp`의 구성**
- 엔진 열거 `Engine { FORTRESS, SWARM }`
- 엔진별 인자 구조 `FortressParams`(비어 있음), `SwarmParams`
- 지도별 행 `MapPolicy`: 가족, 판본, 엔진, 떼 목표 r100 머리 수
- 배정표 `MAP_POLICY`, 찾기 함수 `lookupPolicy`
- `PolicySelector`: 인식 상태(`mapStateCode`)가 바뀔 때만 다시 찾는다.

**`main.cpp`의 차례마다**
- `world.ingest()` 뒤에 배정표로 엔진을 고른다. 떼 엔진이면 `swarm.decide(row)`, 아니면 `planner.decide()`를 부른다.
- 표식 글의 맨 끝, 지도 표식 `map=` 뒤에 ` E=F` / ` E=S`를 한 번 붙인다.

**바꾸지 않은 것**
- **요새 엔진은 stack11의 `Planner::decide()`(plan.cpp) 그대로다.** plan.cpp, plan.hpp, world.*, mapid.cpp, mapdb.hpp, terrdb.hpp, proto.*, geom.hpp는 한 글자도 바꾸지 않았다.
- 엔진 선택은 `decide()` 밖에서 한다. `decide()`가 탐색 시계(`nowPoints()` start)를 읽기 전이다. 그래서 탐색의 명령 수 예산에 들어가지 않는다.

### 표식 ` E=F` / ` E=S`
- 그 차례에 배정표가 고른 엔진이다. 차례마다 한 번, 표식 글의 맨 끝에 붙는다.
- **v0에서 E=S는 "떼 엔진에 배정됨"만 뜻한다.** 그 차례에도 요새 엔진 코드가 돈다.
- 동작 지문은 표식 사건을 건너뛴다(`tools/fingerprint.js` SKIP). 판정기의 표식 한도(512자, 줄 50만, 16MB)에 비하면 4글자는 작다.
- 옛 도구는 표식을 앞에서부터 읽거나 공백으로 자른 낱말로 읽는다. 그래서 끝의 `E=F`는 해석을 바꾸지 않는다.
  - `tools/mech_check.js`: `extra` 낱말로 들어간다.
  - 끝판 추출기: 영향 없음.
  - `map=` 정규식: `\S+`가 공백에서 멈춘다.

## 5. 온라인에 올린다면
- **v0 웨이브는 "같은 시기 기준점 웨이브"다(`EVAL.md` 1절).** 행동이 stack11과 같기 때문이다. 결과로 v0를 채택하거나 기각하지 않는다.
- **확인할 것:**
  - 시간 초과 0, 표식 누락 0
  - `system_report` 3절에서 요새 지도는 E=F, 떼 지도는 인식 뒤 E=S인지
  - 32×16 지도에서 새끼가 E=F로 도는 몫
- **1웨이브짜리 같은 시기 기준점은 검정력이 낮다.** W12 대 W11 보고서에서 새 버전 3웨이브, 참 17%일 때 0.44였다. 주 판정은 합산 기준점(81/900)에 대고, 같은 시기 웨이브는 상대 변화 감시로 쓴다.
