Before starting each next step (even small, reversible ones like creating a branch or editing .gitignore), briefly confirm with the user first, then proceed.

**Why:** 10-03 the user said "앞으로는 나랑 대화할때, 가능하면 가볍게 항상 확인을 하고 진행하자. 우리는 한팀으로 움직여야해" — after I created the `juntegral` branch on my own mid-turn.

**Update 10-03 (later):** user said this was too passive — work semi-autonomously. Commit/push/open PRs on `juntegral` on my own and just report; confirm only `main` merges, server uploads, and direction changes.

**How to apply:** propose the step in one line and wait for an ok; keep the check light (no long option surveys). Same spirit with the meow team: suggest directions, don't pre-assign roles. Related: [[meow-team-repo]], [[upload-only-rule]].

10-04 update: the user said "앞으로 능동적으로 처리해". Handle routine loop/infra decisions on my own (agreed rules, tooling fixes, card housekeeping) and report after. Still ask before: changing direction, server-impacting choices the user hasn't pre-approved, and anything irreversible.
10-04 calibration: "proactive" covers loop/infra housekeeping and agreed rules only. Strategy questions the team is discussing (e.g. QWQ asking for big-map ideas) get decided in conversation first: offer the analysis, don't launch it and then announce it.
