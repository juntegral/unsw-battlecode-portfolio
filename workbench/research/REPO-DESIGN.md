# 새 계통 저장소 설계 (초안, 2026-10-01 01:25 KST)

사용자 결정(2026-10-01 00:55–01:20):
- 점검 선택지 C(새 계통)와 D(판정 재설계)로 간다. "이 방식으로 진행할 레포를 다시 설계하자."
- "국소적인 구현 자체는 엄청 잘 했고, 상대 분석도 열심히 잘 했으니 이걸 기반으로 다시 달려보자."

이 문서는 저장소의 구조, 규칙, 일하는 방식, 판정 규약을 정한다. 봇 전략 자체는 `ENGINE-v1-draft.md`에 있다.

## 1. 왜 새 저장소인가
- `unsw-heuristic`은 "기능 하나 = 토글 하나 + 표식 하나 + 게이트"로 자랐다.
  - 12웨이브 동안 켜진 기능 22개, 꺼진 기능 13개가 한 봇에 섞였다.
  - 확인 도구(`tools/mech_check.js`)도 기능마다 절이 붙어 비대해졌다.
  - 상위 6팀 성적은 15웨이브 1,050판에서 9.0%(81/900)로 제자리다(`research/CHECKPOINT-2026-10-01.md`).
- 새 방식은 "엔진 버전 = 시스템 전체에 대한 가설"이고 판정은 결과로 한다. 바탕 구조부터 다르므로 새로 연다.
- 물려받을 것:
  - 부품 구현의 성과: 지도 인식, 위협 모형, 줍기, 탈출 질주, 포털
  - 전체 모집단 연구들과 그 수치
  - 범용 도구
  - 자료

  bot/              현재 엔진(C++), 역할별 모듈

## 5. 판정 규약(D)
- **주 판정: 상위 6팀 승수를 여러 웨이브 합쳐 본다.** 한 웨이브는 상위 6팀 60판 + DEV 545 10판이다. 기준 9.0%에 대한 단측 0.05 검정력은 다음과 같다(01:20 계산).

| 새 버전 승률 | 1웨이브(60판) | 2웨이브(120) | 3웨이브(180) | 4웨이브(240) | 6웨이브(360) |
|---|---|---|---|---|---|
| 12% | 0.17 | 0.25 | 0.31 | 0.37 | 0.45 |
| 14% | 0.29 | 0.45 | 0.57 | 0.66 | 0.78 |
| 17% | 0.49 | 0.73 | 0.86 | 0.92 | 0.98 |
| 20% | 0.67 | 0.90 | 0.97 | 0.99 | 1.00 |

  - 그래서 새 엔진 버전은 3웨이브(180판)로 판정한다. +8%p(17%)면 86%로 가려진다.
  - 더 작은 차이(+5%p)는 6웨이브가 필요하다. 엔진 버전을 너무 잘게 나누지 않는다.
- **진단 지표 다섯**(웨이브마다, 같은 형식):
  1. r100 머리 수
  2. 자연 진주 섭취 몫(우리/상대)
  3. 왕 계보가 r300–499에 먹은 희생 진주
  4. 끝 최장(우리/상대)
  5. 전멸
  - 지도 가족(엔진이 맡는 지도)별로 나눠 적는다.
- **기능 표식:** 봇에 남긴다. 적용 확인은 "그 기능이 켜진 상황이 오는가"를 보는 진단일 뿐, 채택 기준이 아니다.
- **로컬 판:** 빌드, CPU 한도(한 턴 100M), 시간 초과, 충돌 확인용이다. 흉내 상대 결과로 거르지 않는다(오늘 여러 번 온라인과 어긋났다).
- **사전 등록:** 버전마다 `VERSION.md`에 가설과 판정 기준을 웨이브 전에 적는다. 결과를 본 뒤 바꾸지 않는다.

## 6. 규칙(물려받는 것)
- **원격 작업**
  - 원격 작업은 허용한다. API 키는 화면, 파일, 로그에 남기지 않고 자식 프로세스 환경변수로만 넘긴다.
  - 원격 작업은 `REMOTE-LOG.md`에 적는다.
  - 올리기만 하고 되돌리지 않는다(되돌리기는 사용자 몫).
- **대전 신청**
  - 지금은 비랭크 스크림만 한다(사용자 2026-09-30 21:20).
  - 성적은 상위 7팀 기준이다(00:25). 레이팅과 낮은 팀 판은 쓰지 않는다.
  - 티켓은 상위 7팀 웨이브에 쓴다.
- **분석**
  - 분석은 누적 전체 모집단으로 한다. 분류한 뒤 골라서 정독한다.
  - 앞선 실험체가 1차 표본이다.
  - 핵심 수치는 독립 재계산한다.
  - 토큰을 아끼지 않는다.
- **역할 분담**
  - Codex(gpt-6.1-sol, 추론 max): 딥 리서치와 긴 연구
  - Claude: 전략, 설계서, 판정, 조율
  - 구현 에이전트: 버전 구현
- **기계 한도**
  - 로컬 판은 동시 6판까지다.
  - 디스크 여유 20GB 미만이면 새 판을 멈춘다.
  - 무거운 분석은 nice로 돌린다.

## 7. 일하는 방식(한 버전의 흐름)
1. **설계:** ENGINE.md에 버전 가설 한 줄과 목표 수치를 적는다. 이것이 사전 등록이다.
2. **구현:** 구현 에이전트가 역할 모듈 단위로 짠다. 토글을 쌓지 않는다. 대신 버전을 나눈다.
3. **로컬 점검:** 빌드, CPU, 시간 초과, 진단 지표가 기대한 쪽으로 움직이는지 본다(거르는 용도 아님).
4. **온라인:**
   - 3웨이브 합산으로 판정한다.
   - 웨이브 사이에는 system_report로 진단한다.
   - 3웨이브 뒤 채택 또는 다음 버전을 정한다.
5. **기록:** `VERSION.md`와 `DECISIONS.md`에 적는다. 한 버전이 끝날 때마다 사용자와 짧게 점검한다.

3. ENGINE v1 구현을 시작한다. 옛 부품 이식부터 한다.
