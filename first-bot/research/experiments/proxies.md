# 상위권 흉내 상대(proxy) — 2026-09-29~30

- **목적:** 로컬 상대 4종은 상위권보다 약하고 하는 일이 다르다(음파 없음, 박치기는 hunter만). 그래서 상위권처럼 행동하는 로컬 상대를 만들고, 상위권에 쓴 도구로 얼마나 비슷한지 잰다. `research/PLAN-2026-09-29.md`의 B단계다.
- **만든 것:** `bots/proxy_swarm`(다수 N형), `bots/proxy_elim`(cheji bt형), `bots/proxy_king`(K형). 측정 도구 `tools/proxy_check.js`.
- **원격 작업:** 없다. 대전 신청·업로드·다운로드 0건이다. `bot/`과 기존 상대 4종은 바꾸지 않았다.
- **표기:** 숫자는 모두 스크립트 출력이다. 출처 파일을 절마다 적었다. "목표"는 상위권 값, "비"는 흉내 ÷ 목표다. **사실**과 **해석**을 나눴다.

## 1. 설계

### 1.1 공통 구조
| 파일 | 내용 |
|---|---|
| `pxcore.cpp` | 공통 규칙. 세 폴더에 같은 파일이다(`bots/proxy_swarm`이 원본, `node tools/proxy_check.js sync`로 복사). |
| `pxproto.hpp/.cpp` | 프로토콜 3 입출력. 우리 봇 `bot/proto.*`를 이름공간만 바꿔 복사했다(64비트 음파, 네 방향 발신, 절대 예외 없음). |
| `style.hpp` | 스타일 상수. 폴더마다 다르다. |
| `bot.toml` | C++ 빌드 설정. 각 폴더가 `tools/unswbc`로 따로 빌드된다. |

- 한 드래곤이 한 프로세스다(규칙). 드래곤마다 본 것을 기억한다: 해초·포털 모서리, 진주, 진주 타이머, 자기 몸, 보이는 드래곤, 음파로 들은 아군.
- **대칭 추론:** 세 가설(위아래 뒤집기, 좌우 뒤집기, 180도 회전)을 해초·포털·진주 타이머로 검사한다. 하나만 남으면 거울 칸의 모서리와 진주 타이머를 채운다(거울 칸은 타이머를 공유한다, `rules/pearls.md`).
- **음파:** 매 턴 네 방향으로 64비트를 보낸다. 내용은 (팀, 종류, id, 라운드, 머리 x·y, 길이)와 검사 비트다. 종류는 자기 보고, 왕 중계(K), 적 머리 목격(elim)이다.
- **CPU:** `tools/unswbc run --sandbox` 요약으로 확인했다. Slithery Fight(elim 대 king), Schooltime(swarm 대 king), Trauma(우리 봇 대 elim), 모두 시드 7에서 흉내는 턴당 최대 8.8M 점, p99 8.6M 점이다(한도 100M). 같은 Trauma 판의 우리 봇은 최대 29.7M 점이다.

## 2. 측정 방법
- **목표값:** 상위권 스냅숏 472판(`data/top/snapshot-20260929a.keys`). `tools/fragment_study.js`와 같이 SSS가 고장 난 14판과 SSS 쪽을 뺐다. 그래서 911편(편 = 한 경기의 한 팀)이다. cheji bt 86편, K(Kamikaze, 中国必须人能飞😡) 72편이다.
- **같은 도구:** 경기 특징은 `tools/top_features.js`의 `extract`, 몸 재구성·빈 이웃·진주 행방·박는 비율은 `tools/fragment_study.js`의 `study`로 잰다. 로컬 리플레이도 형식 2라서 그대로 읽힌다. 경기마다 두 편의 요약을 `exp/<이름>/sides.jsonl`에 쓴다.
- **검산:** 다시 계산한 목표값이 관측 문서와 같다. 911편, 유닛 r100 17, 2+2 68.4%, 박치기 편당 20.7(질주 47.6%), 박는 비율 36.2%(무작위 42.8%), 출구 있는 희생 30.9(중앙 r377), 400 이후 최장 먹이의 희생 몫 50.6%. 출처는 `exp/proxy-v2/report-swarm.md`의 목표 열이다.
- **흉내끼리:** 10지도(`maps/online-20260927`). swarm 거울전은 시드 1–3, elim·king 대 swarm은 시드 1–2 양쪽 진영이다. swarm 측정에는 거울전과 교차전의 swarm 쪽을 모두 넣었다(140편).
- **우리 봇:** `tools/eval.js` 표준 방식(10지도 × 양쪽 × 시드 1–2 × 상대 3 = 120판). 같은 도구로 측정했다.
- **온라인 기준:** `data/online/baseline-r1`(상위 6팀 + DEV, 70판)과 `data/online/r1-online`(중위권, 194판)을 같은 도구로 쟀다(`exp/online-*`).

## 6. 알려진 차이와 이유
1. **후반 왕이 작다.** 흉내끼리 r500 최장 0.55–0.74, 우리 봇 상대 r500 23–28(온라인 41).
   - 사실(개발 중 관찰): 시험판의 Trauma 한 경기(`exp/r1-vs-proxies-t4`·`t6`의 `bot__proxy_swarm__trauma__1`)에서 왕 후보를 10라운드마다 추적했다. 길이 8–17에서 해초 미로·자기 몸에 갇혀 stub 분열(2+9, 2+12 …)을 되풀이하며 길이를 잃었다. 경쟁 진주 질주로 막다른 칸에 들어간 경우도 있었다(v2에서 길이 6 이하로 제한했다). 방 확인과 8걸음 생존 탐색을 넣은 뒤에도 같은 경기의 최장은 17–18에 머물렀다.
   - 사실: 희생 진주를 당시 최장이 먹는 몫이 9–13%(목표 18–28%)이고, 400 이후 최장 먹이 중 희생 몫이 18–21%(목표 45–61%)다.
   - 해석: 상위권의 큰 드래곤은 미로에서 덜 갇히고, 희생은 왕 머리 바로 앞에서 더 정확히 일어나는 것 같다. 이 부분의 이동 품질은 재현하지 못했다.
2. **중반 유닛 수가 적다.** 흉내끼리 r300에 0.57–0.66(세 스타일), swarm은 r400에도 0.71이다. 우리 봇 상대 r200은 24–35.5(온라인 45)다.
   - 사실: 우리 봇 상대에서 먹는 양은 비슷하거나 많지만, 죽어서 잃는 길이가 1.0–1.3배다(`exp/r1-vs-proxies-v2/mass-*.md`, `node tools/proxy_check.js mass`). 진행 중인 편당 50라운드 값이다.

| 구간 | 먹은 진주: swarm / elim / king / 온라인 상위 | 사망으로 잃은 길이: swarm / elim / king / 온라인 상위 |
|---|---|---|
| r50–99 | 106 / 100 / 109 / 100 | 73.7 / 66.8 / 76.5 / 58.3 |
| r100–149 | 127 / 118 / 131 / 116 | 107 / 94.3 / 109 / 81.6 |

   - 흉내끼리의 사망 방식 분포는 목표에 가깝다(4.1절: 갇힘 비율 59.4% 대 54.3%). 해석: 우리 봇 상대에서 상위권은 흉내보다 덜 죽으며 떼를 45까지 키운다.
3. **elim은 cheji만큼 깨끗하지 않다.** 사실: cheji는 해초·자기 몸 사망이 0이고 편당 사망이 134다. elim은 갇혀 죽는 것이 편당 131(2.83배)이고, swarm을 16/40만 이긴다(cheji의 상위권 상대 승률 65.1%). 질주도 31 대 81로 적다. 해석: 갇힘 차이가 세기 차이의 큰 몫일 것이다. cheji가 박치기 밖에서 무엇을 위해 질주하는지는 모른다.
4. **큰 드래곤의 박치기.** 적 머리가 옆일 때 길이 5–9·10+가 박는 비율이 12.9%·15.6%(목표 7.0%·6.5%)다. 갇힘 규칙(갇혔을 때 옆 적 머리는 박는다) 때문으로 보인다(해석).
5. **K형 모으기.** king은 희생을 왕 2칸 안에서 26.1%(34.6%) 하지만, 진주를 왕이 먹는 몫은 11.8%(28.4%)다. r400 유닛 17(9.5)로 모으기가 늦다.
6. **음파 내용.** 흉내는 자기 형식을 쓴다. 상위권 형식(예: bread first search)은 흉내 내지 않았다. 우리 봇은 검사 비트로 남의 음파를 버리므로 결과에 주는 영향은 없다고 본다(해석).
7. **Prisoners Dilemma 5마리 판본.** 로컬 지도 파일은 3마리 판본뿐이다. 온라인의 절반은 5마리 판본이다.
8. **표본.** 흉내끼리 지도당 11판(swarm), 4판(elim·king)이고 우리 봇 상대는 상대·지도당 4판이다. 지도 하나의 판별 한계는 G 약 9다(`research/MEASUREMENT.md`, 16판 기준).

## 8. 재현 명령 (저장소 루트, 동시 3판)
```
node tools/proxy_check.js targets --jobs 3                     # 상위권 목표값(캐시 exp/proxy-check/top-sides.jsonl, 약 1–2분)
node tools/proxy_check.js run --label proxy-v2 --pairs proxy_swarm:proxy_swarm --seeds 1,2,3 --jobs 3
node tools/proxy_check.js run --label proxy-v2 --pairs proxy_elim:proxy_swarm,proxy_king:proxy_swarm --seeds 1,2 --both-sides --jobs 3
node tools/proxy_check.js report --label proxy-v2 --bot proxy_swarm --target all
node tools/proxy_check.js report --label proxy-v2 --bot proxy_elim --target cheji
node tools/proxy_check.js report --label proxy-v2 --bot proxy_king --target K
node tools/proxy_check.js summary --runs proxy-v2:proxy_swarm:all,proxy-v2:proxy_elim:cheji,proxy-v2:proxy_king:K
node tools/eval.js --bot bot --label r1-vs-proxies-v2 --opps proxy_swarm,proxy_elim,proxy_king --seeds 1,2 --jobs 3
node tools/proxy_check.js measure --label r1-vs-proxies-v2
node tools/proxy_check.js online --dir data/online/baseline-r1 --out exp/online-baseline-r1
node tools/proxy_check.js online --dir data/online/r1-online --out exp/online-r1-online

```
