## 2. 무엇을 볼 수 있나
- 규칙(`rules/pearls.md`, `rules/execution-order.md`)
  - 라운드 시작마다 모든 칸의 카운트다운이 1 준다. 0이 되면 생성을 시도하고, 성공과 상관없이 U[min, max]에서 새로 뽑는다.
  - 시도는 칸이 비어 있을 때(진주도 몸도 없음)만 성공한다. 대칭 칸은 카운트다운을 같이 쓴다.
- 따라서 볼 수 있는 것
  - 라운드 시작의 자연 생성(첫 차례 전 `tileChange`)은 그 묶음의 시도다.
  - 묶음의 모든 칸이 막힌 라운드의 시도는 흔적이 없다. 몸 재구성과 진주 기록으로 라운드마다 막힘을 계산했다.
  - 첫 시도는 g0 − 1 라운드다(초기 카운트다운 g0 ~ U[min, max]). 가상의 시도가 −1 라운드에 있다고 보면 된다.
- **간격 표본:** 알려진 시도 u 뒤, 나이(r − u)가 min 이상인 라운드가 모두 비어 있다가 생성이 나오면 그 간격은 한 번 뽑은 값이다. 나이 min 이상에서 막힌 라운드를 만나면 "간격 ≥ 그 나이"로 검열한다. 경기 끝도 검열이다.
- **"먹힘 → 다음 생성"은 간격이 아니다.** 카운트다운은 먹힌 때가 아니라 마지막 시도 때 다시 시작한다. 그래서 이 값은 다음 시도까지 남은 시간이고 1–max 사이다. 표에는 참고로 같이 적었다.
- [사실] 로컬 800판(진짜 시도 기록 있음): 관측한 생성 407,834회(묶음·라운드 단위)가 모두 진짜 시도다. "깨끗한" 간격 72,683개가 모두 한 번 뽑은 값이다. 첫 시도는 74,899묶음·판 모두 초기 카운트다운 − 1 라운드다.
- [사실] 서버 8,552판(자연 생성 6,430,543회): 막혔다고 계산한 칸의 생성 0, 대칭 칸이 비었는데 한쪽만 생성 0, 끝 상태 불일치 0이다. 대칭 칸이 카운트다운을 같이 쓴다는 것도 모든 지도에서 맞았다.

## 3. 추정 방법과 불확실성
- **최소 간격:** 막힘이 전혀 없던 한 간격 표본 중 가장 작은 값이다. 95% 하한은 순서통계로 준다: min ≥ 최소 표본 − w(1 − 0.05^(1/n)).
- **최대 간격:** min을 고정하고, 한 간격 표본과 검열을 균등분포 우도로 맞춘다. 95% 구간은 로그우도가 1.92 떨어지는 곳이다. 좁은 범위는 가장 큰 표본이 곧 추정이다.
- **생성 없음(maxGap 0):** 생성이 한 번도 없던 묶음은 max 하한을 낸다. 시작부터의 빈 구간과, 막힘 뒤 빈 구간(정상상태에서 L라운드 동안 시도가 없을 확률 (M−L)(M−L+1)/(M(M+1)))을 함께 쓴다.
- **판본 찾기:** 파일 배치에서 시작한다. 파일로 설명되지 않는 판을 모아 새 배치를 맞춘다. 판마다 두 배치의 우도를 비교해 다시 나누고 되풀이한다(묶음당 하한 −25). 끝으로 판본마다 "깨끗한 배치"(묶음마다 생성 없음 / 파일 그대로 / 새 부류)를 만들고, 그 배치로 다시 나눴다.
- [사실] 합성 확인: 로컬 경기의 실제 막힘 위에 알려진 간격으로 시도를 뽑아 28개 부류 × 3번 맞췄다. 95% 구간 84개 중 82개가 참값을 품었다.
- [사실] 로컬 평가 리플레이로는 넓은 범위를 검증할 수 없다. 시드 1–4만 쓰기 때문에 지도·시드마다 시도 일정이 같다(Trauma 80판에 일정 2가지).
- [사실] 판본 a의 넓은 범위를, 첫 구간(0라운드부터)의 앞부분만 쓴 추정과 전체 추정으로 비교했다(아래 표). 차이는 ±5% 안이다.
  - 전체 추정의 95% 구간이 파일 값을 빼는 것은 Trophy 1–1000과 Default 1–3849뿐이다. 둘 다 첫 100라운드 추정은 파일 값을 품는다.
  - 첫 구간 추정의 구간도 가끔 파일 값을 뺀다(Autarky ≤100 511 [503, 517], Devil ≤200 578 [559, 599]). 공칭 구간은 조금 좁다.

## 6. 만든 지도 파일과 검증 경기
- 파일은 온라인 파일에서 TILE 줄만 바꿨다(해초·포털·대칭·드래곤 줄은 같다). 한 묶음의 두 칸은 같은 값이다.
- 값: 생성 없음 → `0 0`, 파일 그대로 → 파일 값, 새 부류 → 합친 최대우도 추정(min, max).

## 7. 한계
- 넓은 범위(max > 500)의 값은 ±5%로 본다(3절). 게임이 500라운드라 max가 크면 한 판에 시도가 몇 번 없다.
- 새 부류의 끝값은 관측 끝값이다. Queen Of Spades b 1–499는 [499, 507] 안이라 1–500일 수 있다.
- 판본 b 안에서 더 작은 판본은 찾지 못했다. 판본마다 깨끗한 배치 하나로 모든 판이 모순 없이 설명된다. 다만 간격만 조금 다른(예: 1–1000 대 1–1100) 판본이 섞였다면 가리지 못한다.
- 처음에 막혀 있다가 한 번도 생성하지 않은 묶음은 시작 기준 정보가 없다. 막힘 뒤 빈 구간의 정상상태 근사로 하한을 냈다.
- 시간 비교는 대부분 09-29 09Z–23Z 자료다(상위권 자료가 09-29 07:46Z부터다). 09-27·28은 판 수가 적다.

## 8. 봇에 주는 뜻 [추정]
- **경기 중 판본 가리기:** maxGap 0인 칸은 `get_pearl_time()`이 늘 −1이다(`rules/pearls.md`). 시야 안에 a와 b에서 켜짐이 다른 칸이 있으면 첫 라운드에 판본을 안다.
  - Devil: 가운데 x=15, y=5–10(a는 1–30, b는 꺼짐), x=6,7 두 줄(a 1–600, b 꺼짐), (15,1)(16,1)(a 꺼짐, b 1–1).
  - Queen Of Spades: 가운데 x=11–19, y=4–12(b 꺼짐), 왼쪽 x=2–6, y=12–15와 대칭 칸(b만 켜짐).
  - Schooltime: 1–20 칸 x=27–29, y=34–38(b 꺼짐) 등. 켜짐이 다른 묶음이 192개다.
  - Slithery Fight: 가운데 (31,13)(b 꺼짐) 등. 켜짐이 다른 묶음이 153개다.
- **먹이 계획:** Schooltime b는 먹이가 a의 1/3이다. 긴 드래곤을 키우는 계획은 a를 전제로 하면 b에서 틀린다.
- **로컬 평가:** 로컬 지도 한 벌로는 이 네 지도에서 절반의 경기(b)를 못 본다. b 파일을 같이 써야 서버와 같은 먹이 분포가 된다. 지도 폴더에 a와 b를 모두 넣으면 그 지도의 판 수가 두 배가 되니, 지도 비중을 맞추려면 시드를 나눠 준다.

## 9. 재현
저장소 루트에서 실행한다. 네트워크는 쓰지 않는다. 리플레이 읽기는 작업자 4개 이하로 한다.

```
node tools/pearl_layout.js extract --jobs 4                    # data/top + data/online(+g1, g2) → data/pearl_layout/games.jsonl.gz
node tools/pearl_layout.js extract --local exp/eval-r1 --local exp/base-px9d --local exp/base-px9e \
  --local exp/cand-avoid6 --local exp/base-px8 --jobs 4         # 검증용 로컬 800판 → local.jsonl.gz
node tools/pearl_layout.js report                              # 지도별 부류 표 (변경 뒤 전체, 파일 대조)
node tools/pearl_layout.js variants                            # 판본, 비율, 시간대 → data/pearl_layout/variants.json
node tools/pearl_layout.js report --variant all --json data/pearl_layout/groups.json   # 5.1·5.2절 표, 묶음별 수치
node tools/pearl_layout.js build                               # maps/variants/<지도>_b.map (기존 파일이 구간 안이면 그대로)
tools/unswbc run maps/variants/devil_b.map bot bots/proxy3_swarm --sandbox --seed 1 -o exp/pearl-variants/games/devil_b_s1/game.replay
node tools/pearl_layout.js compare exp/pearl-variants/games/*/game.replay                 # 6절 표
node tools/pearl_layout.js report --local                      # 로컬 검증 자료로 같은 표
node tools/pearl_layout.js selftest                            # 2절 로컬 검증, 3절 합성 확인과 첫 구간 표
```
- `extract`는 이미 읽은 판을 건너뛴다. 새 상위권 경기가 쌓이면 `extract`와 `variants`만 다시 돌리면 된다.
- 4절 표, 판본 점수 차, 시작 배치별 판 수, 판당 자연 진주는 `variants` 출력에 있다.
